# Как понять проект и защитить его

Конспект к проекту «Целые числа в системах счисления». Читай по порядку: сначала математика, потом общая схема, потом файлы, потом вопросы.

---

## 1. О чём проект — за 30 секунд

> Это веб-тренажёр по переводу целых чисел между системами счисления с основаниями от 2 до 16.
> Две задачи: перевести число **в десятичную** систему через разрядное разложение и **из десятичной** — последовательным делением с остатком.
> Программа не просто выдаёт ответ: она показывает каждый шаг, а ученик сам находит вклад разряда, очередной остаток и порядок цифр. Ответы проверяет сервер на C#.

Эту речь стоит выучить почти дословно.

## 2. Математика, на которой всё стоит

### Из системы b в десятичную (разрядное разложение)

Каждая цифра стоит в своём **разряде**. Разряды нумеруются **справа налево, с нуля**.
**Вес** разряда номер k равен bᵏ. **Вклад** цифры = значение цифры × вес.
Число = сумма всех вкладов.

Пример: `1A3` в системе с основанием 16 (A = 10):

| Разряд | Цифра | Вес | Вклад | Сумма |
|---|---|---|---|---|
| 2 | 1 | 16² = 256 | 1 · 256 = 256 | 256 |
| 1 | A (=10) | 16¹ = 16 | 10 · 16 = 160 | 416 |
| 0 | 3 | 16⁰ = 1 | 3 · 1 = 3 | **419** |

### Из десятичной в систему b (деление с остатком)

Делим число на b с остатком, потом частное снова делим на b, и так, **пока частное не станет 0**.
Остатки — это цифры нового числа, но **записываются в обратном порядке**: первый остаток — самая правая цифра.

```
419 : 16 = 26, остаток 3    ← младшая (правая) цифра
 26 : 16 =  1, остаток 10 = A
  1 : 16 =  0, остаток 1    ← старшая (левая) цифра
```

Читаем снизу вверх: **1A3**.

**Почему в обратном порядке?** Первый остаток — это то, что «не влезло» в целые шестнадцатки, то есть количество единиц (разряд 0). Каждое следующее деление «сдвигает» число на разряд вправо.

### Граничные случаи

- **Ноль.** `0` в любой системе — это `0`. При делении получается один шаг: `0 = 16 · 0 + 0`.
- **Недопустимая цифра.** В двоичной системе есть только 0 и 1, поэтому `1201₂` — ошибка, и программа подсвечивает двойку.
- **Пределы.** Основания 2–16, числа 0–4095. 4095 = FFF₁₆ = 111111111111₂ (12 единиц), поэтому записи длиннее 12 цифр не бывает.

## 3. Как устроен проект: три части

Удобная аналогия — ресторан:

| Часть | Аналогия | Что делает | Папка |
|---|---|---|---|
| **Ядро** (Core) | повар | считает: разложение, деление, проверка ответов | `src/NumberSystems.Core` |
| **Веб-слой** (Web) | официант | принимает запросы из браузера, передаёт их ядру, несёт ответ обратно | `src/NumberSystems.Web` |
| **Браузер** (wwwroot) | зал | рисует доску и карточки, анимирует, принимает ответы ученика | `src/NumberSystems.Web/wwwroot` |
| **Тесты** | контролёр качества | автоматически проверяет, что повар не ошибается | `tests/NumberSystems.Tests` |

Главная мысль, которую надо уметь объяснить:
**вся математика живёт только в ядре.** Браузер ничего не вычисляет, а веб-слой только передаёт данные. Поэтому ядро можно проверить тестами отдельно и переиспользовать, например в консольной программе.

Как они общаются:

```
Браузер ──(запрос: GET /api/to-decimal?number=1A3&radix=16)──► Веб-слой ──► Ядро
Браузер ◄──(ответ: JSON со списком разрядов или ошибкой)────── Веб-слой ◄── Ядро
```

**JSON** — текстовый формат данных, например `{"value": 419, "radix": 16}`.

## 4. Разбор файлов (в порядке чтения)

### `Limits.cs` — границы задачи

Просто константы: `MinRadix = 2`, `MaxRadix = 16`, `MaxValue = 4095`, `MaxDigits = 12`.
Их держат в одном месте, чтобы при смене границ не пришлось искать числа по всему коду.

### `DigitAlphabet.cs` — цифры 0–F

```csharp
private const string Symbols = "0123456789ABCDEF";
public static char ToSymbol(int value) => Symbols[value];          // 10 → 'A'
public static bool TryGetValue(char symbol, out int value)         // 'A' → 10
{
    value = Symbols.IndexOf(char.ToUpperInvariant(symbol));
    return value >= 0;
}
```

Хитрость: значение цифры — это её **позиция в строке**. `'A'` стоит на 10-м месте, значит A = 10.
`ToUpperInvariant` позволяет вводить `a` вместо `A`.

### `Result.cs` — «ответ или ошибка»

Вместо того чтобы «падать» с исключением при неверном вводе, функции возвращают объект `Result<T>`. В нём лежит **либо** результат, **либо** ошибка (`ConversionError`) с кодом, текстом и **позицией** неверного символа.
Неверный ввод — нормальная ситуация для тренажёра, а не авария. По позиции интерфейс подсвечивает неверную цифру.

### `PositionalExpansion.cs` — перевод в десятичную

Сначала проверки, по порядку:
1. основание от 2 до 16;
2. строка не пустая;
3. нет минуса (числа только неотрицательные);
4. не больше 12 цифр;
5. каждая цифра меньше основания (иначе `InvalidDigit` с позицией).

Потом главный цикл, который и есть разрядное разложение:

```csharp
for (var i = 0; i < digits.Length; i++)
{
    var position = digits.Length - 1 - i;      // номер разряда справа
    var weight = Pow(radix, position);         // вес = основание^разряд
    sum += values[i] * weight;                 // прибавляем вклад

    if (sum > Limits.MaxValue) → ошибка «больше 4095»

    terms.Add(new DigitTerm(position, digits[i], values[i], weight,
        values[i] * weight, sum));             // запоминаем шаг для показа
}
```

Важно: функция возвращает не одно число 419, а **список шагов** (`DigitTerm`): цифру, вес, вклад и накопленную сумму. Из этих шагов браузер и рисует карточки.

`position = digits.Length - 1 - i`: строку читаем слева направо (i = 0, 1, 2), а разряды нумеруются справа (2, 1, 0).

### `DivisionChain.cs` — перевод из десятичной

```csharp
do
{
    var quotient = dividend / radix;    // частное (целочисленное деление)
    var remainder = dividend % radix;   // остаток
    steps.Add(new DivisionStep(...));
    dividend = quotient;                // частное становится новым делимым
} while (dividend > 0);

var digits = new string(steps.Select(s => s.RemainderSymbol).Reverse().ToArray());
```

- `/` для целых чисел даёт целую часть, `%` — остаток.
- `.Reverse()` переворачивает остатки: так получается запись числа.
- **Почему `do…while`, а не `while`?** `do…while` выполняется хотя бы один раз. Для нуля получается один шаг `0 : b = 0, остаток 0`, и ответ «0». С обычным `while (dividend > 0)` цикл для нуля не выполнился бы ни разу, и ответ был бы пустой строкой. Это хороший вопрос на защите.

Десятичную строку от ученика проверяет тот же код, что и в первой задаче: `PositionalExpansion.ToDecimal(input, 10)`. Одна проверка на обе задачи.

### `Exercises/AnswerChecker.cs` — проверка ответов

Три вида заданий (`ExerciseKind`):

| Задание | Что ученик вводит | Как проверяется |
|---|---|---|
| `DigitContribution` | вклад разряда | заново считаем разложение и сравниваем с `Contribution` нужного разряда |
| `NextRemainder` | остаток деления | сравниваем с остатком; засчитываются и «A», и «10» |
| `DigitOrder` | запись числа | сравниваем с итоговой записью `1A3` |

Сервер **ничего не запоминает** между запросами: в каждом запросе приходит всё условие, и правильный ответ вычисляется заново. Кроме ответа сервер возвращает подсказку (`hint`) и полное решение (`explanation`).

### `Exercises/ExerciseGenerator.cs` — случайные задачи

Выбирает случайное основание (кроме 10, потому что переводить из десятичной в десятичную бессмысленно) и случайное число до 1023. Иногда нарочно выдаёт 0.

### `Web/Api/ConversionEndpoints.cs` — адреса API

```csharp
api.MapGet("/to-decimal", (string? number, int radix) =>
    ToHttp(PositionalExpansion.ToDecimal(number, radix)));
```

Читается так: «когда браузер запрашивает `/api/to-decimal`, возьми из адреса `number` и `radix`, вызови ядро и верни результат».
`ToHttp` превращает `Result` в ответ: успех → код **200** и данные, ошибка → код **400** и описание ошибки.

| Адрес | Что делает |
|---|---|
| `GET /api/to-decimal?number=1A3&radix=16` | разложение по шагам |
| `GET /api/from-decimal?number=419&radix=16` | цепочка делений |
| `POST /api/check` | проверка ответа ученика |
| `GET /api/exercise?direction=ToDecimal` | случайное задание |

### `Web/Program.cs` — запуск сервера

Создаёт веб-приложение, подключает раздачу файлов из `wwwroot` (HTML, CSS, JS) и регистрирует адреса API. Строка `AddSingleton(new ExerciseGenerator(Random.Shared))` — это **внедрение зависимостей**: генератор создаётся один раз и передаётся в обработчик автоматически.

### `wwwroot/app.js` — интерфейс

Ключевые функции:

- `api(path, body)` отправляет запрос на сервер (`fetch`) и возвращает JSON.
- `renderTo(data)` получает список разрядов и рисует карточки, веса, вклады, полосу-сумматор.
- `answerContribution()` отправляет ответ ученика на `/api/check` и при успехе показывает вклад на доске.
- `sumContributions()` по очереди заполняет полосу-сумматор и анимирует счётчик суммы.
- `drawLadder()` рисует деление уголком. Шаг номер i стоит в строках i…i+2 и столбцах i…i+1 сетки, поэтому получается «лесенка»: частное каждого шага сразу становится делимым следующего.
- `pickRemainder()` и `fly()`: при нажатии на остаток он «перелетает» в ячейку записи числа.

В начале файла есть комментарий: вся математика на сервере, клиент только показывает.

### `tests/` — автоматические тесты (59 штук)

Тест — маленькая программа, которая вызывает функцию и сверяет результат с ожидаемым:

```csharp
[InlineData("1A3", 16, 419)]
[InlineData("0", 2, 0)]
public void Converts_to_decimal(string digits, int radix, int expected) { ... }
```

Самый сильный тест — **круговая проверка**: каждое число от 0 до 4095 в каждом основании от 2 до 16 переводится туда и обратно, и должно получиться исходное число. Это 15 × 4096 = 61 440 проверок за доли секунды.

Запуск: `dotnet test`.

## 5. Что происходит после нажатия кнопки (трассировка)

Ученик ввёл `1A3`, выбрал основание 16 и нажал «Построить»:

1. `app.js`, функция `loadTo()`, отправляет `GET /api/to-decimal?number=1A3&radix=16`.
2. `ConversionEndpoints` принимает запрос и вызывает `PositionalExpansion.ToDecimal("1A3", 16)`.
3. Ядро проверяет цифры, считает три разряда и возвращает `Result` с тремя `DigitTerm`.
4. `ToHttp` превращает результат в ответ 200 с JSON.
5. `renderTo()` рисует три карточки, веса и плашки «?».
6. Ученик вводит `160` для разряда 1, и `POST /api/check` отправляет `{kind: "DigitContribution", number: "1A3", radix: 16, index: 1, answer: "160"}`.
7. `AnswerChecker` заново считает разложение, находит разряд 1, сравнивает 160 = 160 и отвечает `correct: true` с объяснением `A · 16¹ = 10 · 16 = 160`.

Если ввести `1201` в двоичной: на шаге 3 ядро вернёт ошибку `InvalidDigit, position: 1`, сервер ответит 400, а браузер подсветит двойку.

**Шаг 1. Консольная программа: перевод в десятичную.**

```

```

Напиши функцию `int ToDecimal(string digits, int radix)` с циклом по цифрам. Проверь на `1A3` и 16 (должно быть 419).

**Шаг 2. Перевод из десятичной.** Функция `string FromDecimal(int value, int radix)` с циклом деления. Проверь на 419 и 16, а потом **обязательно на 0**.

**Шаг 3. Проверка ввода.** Что будет с `"12"` в двоичной? С пустой строкой? С `"-5"`? Добавь проверки.

**Шаг 4. Тесты.** `dotnet new xunit`. Напиши 5–10 тестов на свои функции. Попробуй круговую проверку.

**Шаг 5. Веб-сервер.** `dotnet new web`. Добавь один адрес `MapGet("/api/to-decimal", ...)`, который вызывает твою функцию. Открой в браузере `http://localhost:5000/api/to-decimal?number=1A3&radix=16`, и должен появиться JSON.

**Шаг 6. Простая страница.** `wwwroot/index.html` с полем ввода и кнопкой. JS делает `fetch` и выводит результат текстом.

**Шаг 7. Визуализация.** Только теперь карточки, шаги и анимации.

## 7. Вопросы, которые могут задать

**— Почему C# и ASP.NET Core?**
Строгая типизация ловит ошибки ещё до запуска. ASP.NET Core — стандартный способ делать веб-приложения на C#, и Minimal API позволяет описать адрес одной строкой.

**— Зачем делить на три части? Почему не написать всё в одном файле?**
Каждая часть отвечает за одно. Математику можно проверить тестами без браузера и сервера. Если завтра понадобится мобильное приложение, ядро останется тем же.

**— Почему считает сервер, а не JavaScript в браузере?**
Правила (что A = 10, что засчитывать «A» и «10» как один ответ) записаны в одном месте, на C#, и покрыты тестами. Иначе их пришлось бы дублировать на двух языках.

**— Как обрабатывается ноль?**
Цикл `do…while` выполняется хотя бы раз, поэтому для нуля получается шаг `0 = b · 0 + 0` и запись «0». Отдельного `if` для нуля нет.

**— Что будет при вводе неверной цифры?**
Ядро вернёт ошибку `InvalidDigit` с номером позиции, сервер ответит кодом 400, а интерфейс подсветит неверный символ.

**— Почему ограничение 4095?**
Это условие задачи: небольшие числа удобно считать вручную. 4095 = FFF₁₆ = 2¹² − 1, ровно 12 двоичных разрядов.

**— Почему остатки записываются в обратном порядке?**
Первый остаток — число единиц (разряд 0), то есть самая правая цифра. Каждое деление переходит к следующему разряду.

**— Что такое `record`?**
Короткий способ описать класс-«запись» с данными. `DigitTerm` и `DivisionStep` — записи, которые просто хранят значения одного шага.

**— Что такое `Result<T>`, почему не исключения?**
Исключения — для неожиданных сбоев. Неверный ввод ученика — ожидаемая ситуация, поэтому функция честно возвращает «ответ или ошибку», и вызывающий код обязан её обработать.

**— Можно ли подсмотреть ответ?**
Да, в инструментах разработчика браузера видны все шаги. Для тренажёра это допустимо. Для режима контрольной пришлось бы хранить ответ на сервере и выдавать задачу по номеру.

**— Как вы проверили, что программа работает правильно?**
59 автоматических тестов. Главный — круговая проверка: все числа 0–4095 во всех основаниях 2–16 переводятся туда и обратно без потерь.

**— Что такое API / JSON / GET / POST / 200 / 400?**
API — набор адресов, по которым браузер обращается к серверу. JSON — формат данных. GET — «дай данные», POST — «прими данные» (ответ ученика). 200 — «всё хорошо», 400 — «неверный запрос» (например, неверная цифра).

## 9. Словарик

| Слово | Простыми словами |
|---|---|
| Основание системы | сколько разных цифр в системе (2 — двоичная, 16 — шестнадцатеричная) |
| Разряд | позиция цифры в числе, считая справа с нуля |
| Вес разряда | основание в степени номера разряда |
| Вклад | цифра × вес |
| Класс / `static class` | набор функций; `static` — не нужно создавать объект, чтобы их вызвать |
| `record` | класс для хранения данных |
| Цикл `do…while` | цикл, который выполняется минимум один раз |
| `%` | остаток от деления |
| LINQ (`Select`, `Reverse`) | удобные методы для работы со списками |
